## Ways to use models here

Start with the first and go further only for a reason.

1. **Stay in this session.** Work on the model you are running. Right for small, reversible changes and for work that already has its context here.
2. **A subagent of your own harness.** <Name the harness's subagent tool and the models it accepts.> Right for wide reads, independent work that can run in parallel, and keeping this session's context small.
3. **A worker on another agent** (`spawn-worker`). <One line per way this computer has to start one, as the survey found: by another product's CLI run headless, or through an installed environment, only when the user allowed it and only in a session that `detect.sh` says runs inside it. Name the agents and when each one suits the work. Name the adapter section that holds the command (the target's Start me from outside, or the environment's Launching harnesses) instead of copying it.> Right when another agent's model fits the work better than yours.
4. **Several models together** (the `swarm`, `arena`, `interrogate`, and `reflect` skills). <Only when more than one model is reachable. State the user's answer about how readily to do this.> Right for judgment that could split, changes that are costly to undo, and large independent batches.

## Before you spawn

- Recheck only what you are about to use: the CLI is still on `PATH`, the model id is in `inventory.md`, and, for an environment's way, that `../resolve-capability/scripts/detect.sh` prints that environment in this session. If an id is missing, use another id that is in `inventory.md`. Never guess one.
- Remaining usage cannot be read here. If a start fails on a limit, run that seat on another agent for this run, say so in the reply, and change nothing in this skill.
- Say in the reply which model you chose and why, in one line.

## When a task does not match this skill

Decide which kind of mismatch it is.

- **A stable fact is wrong** (a flag a product refuses, a model that is gone). Ask the user. On yes, fix `inventory.md`: a model that is gone leaves its product's Models line, and a refusal or other quirk goes under `## Quirks seen here` with the date and the product version. Append a line to `log.md`. When the quirk would hold on every computer, tell the user it belongs in that product's adapter, because pstack ships the adapters. A wrong mechanism in an adapter is not fixed here either.
- **A preference no longer fits.** Ask the user. On yes, edit the sentence under `## Preferences` or add a branch to it, and append a line to `log.md`.
- **A transient state** (a limit, no network). Substitute for this run, say so in the reply, and change nothing.

Edit only files in this directory, and only after the user agrees.
